# Fixed cloud Data fault campaign

This controller extends the reviewed Modern cloud persistence path, not the
physical Mac or SSD. The existing persistence entry point and evidence remain
unchanged. A separate fixed launcher accepts only canonical case numbers0..59;
it cannot accept paths, device settings, backend plans or commands.

## Execution and evidence

The outer trusted-main controller independently builds the same target twice,
checks reproducibility, packages immutable boot input, pins the launcher image
and records exact tool hashes and firmware sizes. Each case invokes a separate
new container through the existing inspect-before-start confinement check.
The fixed source revision is data/build input, never outer controller authority.

Each container owns one fresh public synthetic Data identity/key and System
image. It uses the reviewed fault scenario's two whole VM lifetimes, frozen
authenticated disk oracle and recovered Files pixels. Only the challenge is
typed in the first VM; the second receives F1 and read-only Data. There is no
guest network, host/device passthrough, owner data, or retained firmware channel.

Each returned capture is retained verbatim and independently checked before
the next case. Image/key/challenge reuse fails immediately. After all sixty
positional cases, the aggregate validator repeats independent content validation.
The manifest preserves each invocation's exact created/exited container receipt
and the shared source, binaries, boot and tool-image identities. Content
validation is not relabeled as standalone provenance validation or M4 completion.

## Bounds and failure behavior

Case execution uses at most300 seconds and the remaining40-minute campaign
budget. Captures are1..8MiB each and at most384MiB combined. Aggregate checking
has its existing600-second bound; the full workflow has a60-minute deadline.
Failure stops the campaign without retries or skipping cases and preserves the
bounded failing capture when one was returned. Existing cleanup stops/removes
only exact containers created and identity-bound by this invocation.
No source, images, caches, owner files or local storage are deleted.

## Before dispatch

The successful retained persistence trace must confirm the independently
predicted Data request geometry. The complete controller/helper/recipe closure
requires independent review and exact-head cloud source checks, then a reviewed
merge to trusted main. Dispatch must name the exact reviewed runtime source.
No source-only check or inert orchestration test counts as a guest fault run.
Signed Settings replacement, System-only recovery, cryptographic completion
and final M4 acceptance remain separate obligations.
