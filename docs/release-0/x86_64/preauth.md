# x86-64 Prompt 7A Static Candidate

Status: non-executing certification preparation

No current candidate profile identity exists; M2–M5 must regenerate every candidate identity through the frozen ADR 0022 transaction DAG before Prompt 7 can be rerun. The single planned candidate profile `r0-x86_64-preauth-v1` will fix: x86-64, QEMU `q35`, TCG, two CPUs, 512 MiB RAM, OVMF code and disposable variables/disk, serial stdio, no display, no network, no host sharing, no passthrough, no clipboard, no elevation, emulator sandbox required, 60-second timeout, 5-second termination grace, and 1 MiB output cap. AArch64 and Tier 0 remain uncertified and unauthorized.

`preauth_entry.S` is a deliberately bounded non-executing R0-003 fragment. It fixes the R0-002 x86-64 register ABI (`RDI` address and `RSI` length), validates the pre-copy null/length/alignment envelope, and contains no source acquisition, mappings, interrupt setup, timer setup, device authority, networking, storage service, IPC, or later-release behavior. The static artifact is not evidence that boot works and is never loaded during Prompt 7A.

The assembly invariant is that `_start` is entered only in 64-bit mode with a 16-byte-aligned writable stack, interrupts disabled or immediately disabled, direction flag clear, and Root/Recovery retaining the immutable DMA-revoked entry slice. This fragment does not dereference `RDI`; the complete adapter remains subject to Prompt 7 review and R0-003 execution evidence after separate authorization.

The M2 build will use only `/usr/bin/as` from the pinned base OCI closure and `/usr/bin/ld.lld-19` from the signed Debian snapshot closure, emitting no dynamic interpreter, no build ID, and no target-linked dependency; CI will build it twice in distinct clean output directories and compare the ELF bytes before static metadata inspection.

In M2–M5 the host closure will be statically extracted without running package maintainer scripts, normalized to one epoch, built twice with no cache, and saved twice under repository output; CI will require exactly the approved 36-package no-recommends set, including strict signed-snapshot source package name/version provenance on every binary row, will fully validate each raw Docker export before extraction, project only the rooted graph into the canonical archive with dangling store metadata excluded, and require byte-identical canonical archives with exact `repositories`, manifest, config, layer, diff-ID, and loaded-image binding before using the derived image. Today, executable validation of that shape exists only for the delivered base export inside M1.6's untrusted delivery route.

For the future pinned Docker-driver `--load` route, Buildx `containerimage.digest` is a typed Docker config ID, not a distribution-manifest digest. M2 CI must separately bind that value to `containerimage.config.digest` and the loaded image ID, while the byte-present canonical OCI index, selected OCI manifest digest, ordered layer-descriptor-set digest, ordered rootfs-diff-ID-set digest, platform, media types, sizes and canonical archive digest remain distinct attested identities. The index descriptor canonically omits its optional platform object, binds the exact manifest digest/size/media type, and allows only the exact checked-out-head `io.containerd.image.name` and `org.opencontainers.image.ref.name` annotations. `linux/amd64` remains independently fixed by the validated config and loaded-image evidence.

ADR 0022 replaces that provisional pipeline with two explicit boundaries. The frozen `closure-input-lock-v4` contains only immutable external inputs and policy versions. M1.5 removed the provisional workflow, parsers, launcher types, output/disk producers, and prepared evidence from production reachability. M1.6 adds `preauth-input-bundle-v1` solely to deliver the approved external bytes: the networked producer has no secrets or authority and cannot build source or emit a transaction graph. A separate networkless `preauth-transaction` process treats every delivered byte as untrusted, validates canonical framing and complete inventory availability, and retains the M2-incomplete refusal. M2 will add independent signature/lock validation, private construction, no-replace publication and one immutable `transaction-graph-v1`. `preauth-session` remains a later boundary gated by exact CI attestations, clean reviews and separate owner authorization.

The transaction graph gives distinct types to raw and canonical OCI representations, source, lock, package/signature/license closure, tools, firmware, artifact pair, immutable disk seed/initial bytes, profile/command, execution host, supervisor, resolver, spawner, wrapper, resource controller, bundle, and publication receipt. The committed input lock contains none of those source-dependent output identities. Superseded records are now reachable only as dedicated negative migration fixtures or historical documentation, enforced by the machine-readable cutover manifest and CI gate.

All permitted work executes host compilers, static inspectors, and synthetic doubles only. It never executes the candidate, QEMU, firmware, an emulator, a VM, a guest, a device, AWS authority, or a real spawner.
