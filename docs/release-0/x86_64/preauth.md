# x86-64 Prompt 7A Static Candidate

Status: non-executing certification preparation

The sole candidate profile is `r0-x86_64-preauth-v1`: x86-64, QEMU `q35`, TCG, two CPUs, 512 MiB RAM, OVMF code and disposable variables/disk, serial stdio, no display, no network, no host sharing, no passthrough, no clipboard, no elevation, emulator sandbox required, 60-second timeout, 5-second termination grace, and 1 MiB output cap. AArch64 and Tier 0 remain uncertified and unauthorized.

`preauth_entry.S` is a deliberately bounded non-executing R0-003 fragment. It fixes the R0-002 x86-64 register ABI (`RDI` address and `RSI` length), validates the pre-copy null/length/alignment envelope, and contains no source acquisition, mappings, interrupt setup, timer setup, device authority, networking, storage service, IPC, or later-release behavior. The static artifact is not evidence that boot works and is never loaded during Prompt 7A.

The assembly invariant is that `_start` is entered only in 64-bit mode with a 16-byte-aligned writable stack, interrupts disabled or immediately disabled, direction flag clear, and Root/Recovery retaining the immutable DMA-revoked entry slice. This fragment does not dereference `RDI`; the complete adapter remains subject to Prompt 7 review and R0-003 execution evidence after separate authorization.

The build uses only `/usr/bin/as` from the pinned base OCI closure and `/usr/bin/ld.lld-19` from the signed Debian snapshot closure. It emits no dynamic interpreter, no build ID, and no target-linked dependency. CI builds it twice in distinct clean output directories and compares the ELF bytes before static metadata inspection.

The host closure is statically extracted without running package maintainer scripts, normalized to one epoch, built twice with no cache, and saved twice under repository output. CI requires exactly the approved 36-package no-recommends set, including strict signed-snapshot source package name/version provenance on every binary row. It fully validates each raw Docker export before extraction and projects only the rooted manifest/config/ordered-layer/OCI-manifest/repositories graph into the canonical archive; dangling Docker-store metadata is excluded before evidence and remains forbidden in the final archive. It requires byte-identical canonical Docker archives and verifies canonical order/metadata, the exact canonical `repositories` tag-to-final-layer binding, manifest, config, layers, diff IDs, and actually selected image ID before using the derived image.

For the pinned Docker-driver `--load` route, Buildx `containerimage.digest` is a typed Docker config ID, not a distribution-manifest digest. CI separately binds that value to `containerimage.config.digest` and the loaded image ID, while the byte-present canonical OCI index, selected OCI manifest digest, ordered layer-descriptor-set digest, ordered rootfs-diff-ID-set digest, platform, media types, sizes and canonical archive digest remain distinct attested identities. The index descriptor canonically omits its optional platform object, binds the exact manifest digest/size/media type, and allows only the exact checked-out-head `io.containerd.image.name` and `org.opencontainers.image.ref.name` annotations. `linux/amd64` remains independently fixed by the validated config and loaded-image evidence.

The closure discovery evidence separately hashes the Debian archive keyring, canonical non-security and security InRelease sets, package/source manifest, license manifest, and acquisition policy and compares every field to the committed lock before construction. Push and pull-request workflows bind their separate CI attestations to the explicitly checked-out commit; event merge refs and mismatches fail before acquisition. Committed prepared records contain no stale commit or run claim. These operations execute host compilers, static inspectors, and test doubles only. They never execute the candidate, QEMU, firmware, an emulator, a VM, a guest, a device, or AWS authority.
