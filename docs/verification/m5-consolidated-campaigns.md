# M5 consolidated runtime acceptance campaigns

These are fixed synthetic cloud cases, not a production networking policy,
new device entitlement, or authority to execute on the owner's Mac/SSD.
Normal Alpha builds do not select the fault/expiry configuration flags.

## Closed-peer network

The existing two-VM, inherited socket-pair, no-Internet controller remains.
Peer B's test-only Link adapter changes three already-authorized frames
(malformed IP version, truncated IP/UDP and bad UDP checksum), drops exactly
one send, then passes subsequent frames unchanged. The actual captures must
contain exactly the planned bytes; screenshots distinguish no delivery from
the next valid delivery. Six subsequent datagrams exercise the four-entry
application receive queue. This is bounded queue-overload coverage, not a
claim about line-rate NIC stress or all network attacks.

The expiry variant uses the real guest clock and a fixed shorter grant;
after expiry both clients must refuse and no frame may appear. Normal grant
duration is unchanged. Explicit close is sticky. A separate case terminates
the peer Terminal and confirms the other peer and Files remain usable.
This is application/network-service peer loss, not a claim that the paired
controller keeps one VM alive after the other QEMU process fails.

Existing pure tests retain stale full-width identities, ingress budgets,
driver failures and revocation checks. Claims must distinguish those tests
from actual cloud observations.

## Integrated same-data System journey

After the independently built Notes and Counter, scoped deterministic agent,
profiles, real peer traffic and fresh private-document read have succeeded,
fresh owned cloud containers perform these fixed transitions on the SAME
validated frozen Data bytes and exact Alpha boot images:

1. Install signed Settings generation 2; show its new UI and spacing; reopen
   private Notes and shared Files without rewriting their documents.
2. Reject the deliberately invalid-signature bank entry from factory state;
   compare every System byte with the existing independent transaction oracle.
3. Boot the actual installed System, fault Settings, observe fallback and the
   old UI, then reopen the same private/shared documents.
4. Copy the actual validated installed System and flip exactly its two fixed
   package-header bytes in a new synthetic System fixture. Boot must repair
   automatically, preserve every non-target System byte, and retain Data.
5. Boot the ACTUAL repaired System again, read private/shared documents,
   reject a stale update, and verify no disk mutation.

No owner disk or Data byte is an injection target. Each phase has new firmware
scratch, whole-VM/backend joins, exact tool/topology/QMP provenance, full
framebuffer equality, bounded failure receipts, no unexpected packets,
same-data continuity and exact System bytes. Expected bytes are not evidence:
later phases require successful actual prior install/repair receipts.

## Completion

Source compilation or a validator self-test does not complete M5. Keep the
implementation draft until these exact-source runtime cases, node execution,
final independent review and release acceptance pass. Local deterministic
agent callbacks are not Pal, inference or an OS-wide autonomous agent service.
The x86_64 Foundation node is not a microcontroller port; compact/wide GUI
profiles are presentation profiles, not additional supported physical devices.
